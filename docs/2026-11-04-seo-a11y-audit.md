# SEO and accessibility audit: nestedreader.app (2026-11-04)

**Bottom line:** the page was already in good shape. axe-core found no violations, every text colour passes AA in both themes, and the title, canonical, landmarks, headings and alt text were all right. This branch fixes six smaller things. The biggest one for people: screen readers now say "Command Shift Return" instead of reading out the ⌘⇧↵ symbols. Nothing looks different on screen. The before and after renders match pixel for pixel at 1280px and 390px wide.

Branch `overflow/nestedreaderseo`, off `origin/main` at `4eca99d` (version 0.2.23). Nothing was published, and nothing was sent to IndexNow or any search engine.

## What I checked, and how

- **Source:** `index.html`, `styles.css`, `script.js`, `robots.txt`, `sitemap.xml`, `llms.txt`, `design/brief.md`, `design/rubric.md`, `design/publish.mjs`.
- **The live site:** plain GET requests only, at 00:03 CT. The live `index.html`, `robots.txt` and `sitemap.xml` match `main` byte for byte.
- **axe-core 4.14.0**, run offline in headless Chrome against a local copy of the page with the Fathom script removed, so no pageview was sent. Tags: wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa, best-practice.
- **Contrast:** computed from the colour tokens in `styles.css`. The oklch values were converted to sRGB, and translucent colours were blended over their real background.
- **Media:** `ffprobe` on the demo videos.

## Not fixed: for Kevin to decide

1. **`/favicon.ico` returns 404.** Browsers use the declared SVG and PNG icons, so this is cosmetic. Some tools still ask for `/favicon.ico` directly. To fix it, add a `.ico` file and put it in `publish.mjs`'s file set, since that script only publishes files the page links to.
2. **The 404 page is plain text from the host.** It's `text/plain` from here.now/Cloudflare. A small `404.html` with a link home would help, if here.now supports one. I didn't check, because that would mean calling here.now.
3. **`/index.html` also returns 200.** The canonical tag already points search engines at `/`. A Cloudflare redirect rule would be cleaner, but this is low priority.
4. **No `/privacy` page, while Fathom runs on the site.** This is already its own queued task, so I didn't touch it here.
5. **`applicationCategory: "ProductivityApplication"`** is valid schema.org. As far as I remember, it isn't one of the app types Google lists for software rich results; those include `BusinessApplication`, `UtilitiesApplication` and `ReferenceApplication`. I couldn't confirm this, because I wasn't allowed to fetch Google's docs. It also doesn't matter yet: Google shows a software rich result only with `aggregateRating` or `review`, and the page shouldn't invent either one.
6. **No `softwareVersion` in the JSON-LD.** `version.yml` only rewrites `<span data-version>`. Its perl line could set a `"softwareVersion"` field too. I didn't change it, because that workflow commits to `main` and publishes.
7. **Version bumps don't update the sitemap's `lastmod`.** That's fine: a version number isn't a real content change. Bump the date by hand when the copy changes.
8. **The ghost buttons' border is 1.6:1 (light) and 1.8:1 (dark).** This still passes WCAG 1.4.11, because the "GitHub" text identifies the button. Raising the border to about 3:1 would make the button's edge easier to see.
9. **Links that open in a new tab** (GitHub and the two source links) don't say so. This is only an advisory technique (WCAG G201), not a failure.
10. **The h1 is the tagline, "Highlight your understanding."** It doesn't name the product. The title, the lede and the JSON-LD do, so this is a copy decision, not a bug.
11. **Not SEO or accessibility, but I noticed:**
    - The header's "Download" link fires the Fathom `download_click` event, but it only scrolls to `#install`. That counts one download intent twice when someone clicks it and then clicks the real button.
    - `design/rubric.md` still says "no third-party requests". Fathom now loads from `cdn.usefathom.com`, which was a deliberate change in #3.
    - In dark mode the page fetches the light poster first, then switches to the dark one.
